# 最终报告写作与验收

下面的统计字段与校验器对应，数值使用整数且不加千位分隔符。
版本基本信息的子项使用“旧版本”“新版本”，避免两个相同版本标签的歧义。
示例中的占位说明须以本次真实数据替换。

~~~markdown
# Crusader Kings III A → B 极详细对比分析报告

- **游戏分支**:
  - 旧版本: 读取旧版 game_branch
  - 新版本: 读取新版 game_branch

  - 新版本: 读取新版 game_commit
- **引擎分支**:
  - 旧版本: 读取旧版 engine_branch
  - 新版本: 读取新版 engine_branch
- **引擎提交**:
  - 旧版本: 读取旧版 engine_commit
  - 新版本: 读取新版 engine_commit

- **旧版文件总数**: 0

## 分析覆盖

- **已分析文本文件数**: 0

说明排除目录、扫描口径、未复核范围，以及跳过原因。这里的“已分析”指脚本证据提取。

## 执行摘要

概括已经核实的重要变化及不确定范围。

## 关键变更

### 变更名称

- **证据**: 游戏源码相对路径、旧版/新版行号或脚本标识。
- **代码事实**: 哪个条件、效果、数值或调用发生了变化。
- **影响推断**: 对应作用域和条件下可能产生什么影响，注明推断依据。
- **待验证**: 运行时行为、遗漏依赖或其他尚不能确认的部分。

展示连续的旧/新代码或 unified diff，保留必要上下文。新增、删除文件明确说明缺失的一侧。
截断时说明省略内容；仅必要时给策略建议，并解释成立条件。

## 其他变化与限制

覆盖小改动、未分类项及二进制变化，明确不能由文件规模证明玩法重要性。

## 附录 B: 生成信息

- **报告生成时间**: 读取 metadata.final_generated_at，含时区
- **分析模型**: 实际模型全名；完整版本不可用时明确注明
- **协作人**: XenoAmess
- **深度分析文件数**: 0
- **LLM复核文件数**: 0
~~~

模板没有要求每个变更都具有策略意义。无需为次要变更重复一整套空洞说明。
相同逻辑只解释一次；相关变更通过报告内章节关联。

B 站版需要的全部内容必须内嵌；允许保留游戏源码路径，不允许依赖同目录其他产物。
两份最终报告本来就禁止表格，因此转换脚本只复制满足约束的报告；遇到表格或产物引用会报错，不会逐行删改代码。
若两版内容相同，可以使用 generate_bilibili_version；若做阅读适配，保持统计、结论和证据一致。

## 完成解读后更新证据元信息

metadata.analysis_model 写实际使用的模型，不能沿用历史 MiniMax 标签。
metadata.final_generated_at 写最终完成时间，例如 2026-09-30T16:30:00+08:00。
metadata.llm_review.performed 设为 true，reviewed_paths 只包含实际核实的候选文本文件相对路径。
候选清单是变化文件中非二进制的部分；不得加入未变化文件或二进制文件凑数。
reviewed_paths 与脚本 deep_diffs 不必相等：Agent 可以额外复核脚本因限制跳过的文本。
不要改动扫描统计来迁就写好的报告。

## 验收命令

从仓库根目录运行，路径替换为本次 artifacts 中的实际名称：

~~~powershell
py -3 .sisyphus/skills/ck3_version_analyzer/scripts/validate_report.py --data "输出目录/diff_report.json" --report "输出目录/版本前缀_极详细对比分析报告.md" --bilibili "输出目录/版本前缀_极详细对比分析报告_B站专栏版.md"
~~~

校验器核对 schema、统计、覆盖分区、版本信息、最终生成信息、表格和 B 站产物引用。
校验失败时根据错误修复。源码解释和模型复核清单的真实性仍需人工/Agent 审查，不能由格式检查证明。
